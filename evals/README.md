# Independent offline evaluation

Run from the repository root:

```powershell
.venv\Scripts\python.exe -m evals.runner --output reports/eval-baseline-run
.venv\Scripts\python.exe -m evals.runner --output reports/eval-sdk-mock-run --sdk-mock
```

Use a new output directory for each run. `results.json` and `report.md` are
written without overwriting existing results. Exit status is 0 when all required
cases pass, 1 for a failed case/grader, and 2 for invalid setup/report output.
The optional SDK-mock command needs `.[agent]`, but neither mode reads an API key
or calls an API. On systems that sandbox local asyncio socket pairs, SDK-mock may
need a permitted local test process; do not disable network isolation to obtain
real model access.

## Separation and provenance

- `fixtures/*.csv` and `fixtures/cases.json`: manually authored readings and
  expected events with independent case IDs/versions and timing tolerances.
  They are not generated by `analyze` or `generate_samples`.
- `cases.py`: schema validation, fixture SHA256 and loader only.
- `graders.py`: one-to-one event matching, peak fact checks, evidence/coverage,
  required tool order, CSV prompt-like text handling and rejection guards.
- `sdk_mock.py`: local scripted model returning actual SDK tool calls and
  structured results copied from tool responses, not from expected labels.
- `runner.py`: executes cases, records failures and exits nonzero when required
  checks fail.
- `results.py`: scoped aggregation and JSON/Markdown reports.

The initial suite covers normal logs; inclusive trigger/recovery thresholds;
subthreshold and unconfirmed runs; active events; missing/gap-interrupted timers;
repeated same-code events; signed charge/discharge conventions; multiple cells
and temperature probes; opt-in bounds/stuck/spike heuristics; and instruction-like
CSV text treated as invalid readings rather than authority.

## Metric definitions

Each true positive must match one manual event by code, rule ID, sensor field,
channel ID, status and all start/confirmed/recovered times within that case's
declared tolerance. Matching is one-to-one: duplicated outputs are false
positives. Signed peaks are separately compared with a numerical tolerance of
`1e-9`. Null recovery times must remain null.

Precision = TP/(TP+FP), recall = TP/(TP+FN); undefined denominators are JSON null
and Markdown N/A. Evidence checks additionally compare each cited fact with the
issued log evidence, enforce unique citations and verify the application-computed
coverage counts. Adversarial graders deliberately submit fabricated peaks/times,
unissued citations, duplicates and false-full declarations and require rejection.

These results describe this small synthetic regression suite only. They are not
real-battery accuracy, model diagnosis quality, general prompt-injection safety,
or a measured latency/cost benchmark. Real model evaluation remains **not
measured**. SDK request counts are simulated turns; token fields are explicitly
unmeasured and actual API calls/charged cost are zero. A future real-model mode
must require separate authorization and a user-owned key; it is intentionally
absent from this offline harness.
